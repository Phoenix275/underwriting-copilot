# PRD Addendum — 7/28 Review Feedback

**Date:** 2026-07-28 · **Status:** all sections shipped this date · supplements `PRD_2026-07-26.md`

Feedback round covering the demo narrative, executive reporting, decision governance,
integrations, and the knowledge-assistant request (previously parked as P1 — now built
as an offline embedded assistant, keeping the no-external-calls constraint).

---

## §A — SHIPPED · Executive rail: numbers first, sized by importance

The "Book at a glance" rail inverted its hierarchy: the **value is now the dominant
element** (mono, large), the description a small uppercase caption beneath it. Size
encodes importance — operating income largest (31px, colored), combined ratio and
coverage accepted next (24px), context rows smallest.

## §B — SHIPPED · Operations admin can change recorded decisions

Ops previously only *watched* the decision feed. Now, mirroring manager authority but
with a distinct audit identity:

- Every decision-trail row carries **↺ Reopen** and **Amend → Approve/Decline**.
- Amendments require a written reason, record what they superseded, and log as
  **OPS AMENDMENT** (vs the manager's MANAGER OVERRIDE) — the trail always shows
  *who* acted and under which authority.
- The same controls appear on the case file for the admin role.

## §C — SHIPPED · UW Guide — embedded knowledge assistant (Knowledge Bot)

A chat assistant available on every screen after sign-in (floating button). Fully
**offline by design**: a curated knowledge base over the platform's own guidelines,
product rules and process, answering from the same constants the engine runs on
(decision lines, requirements grid, routing tiers) — so the bot can never drift from
the product, and nothing leaves the file.

Coverage: decision bands, 6-check conflict screen, DOB/smoker policy, affordability,
age×amount requirements grid, desk routing & authority, SLA/TAT, evidence-anchored
weights, model composition, STP economics, executive P&L, decision-change authority,
exports, products, roles, appetite, integrations, NIGO. Plus **live case lookups**:
give it a case ID (or open a case and ask "why is this case here?") and it reads the
case's actual score, drivers, conflicts, affordability, routing and any recorded
decision. A pilot can swap the retrieval layer for a hosted LLM without changing the UI.

## §D — SHIPPED · Stronger introduction + end-to-end demo flow (tour)

- **Intro**: two new opening steps place the product in the insurance value chain
  (distribution → intake → underwriting → issue → claims) and name the pain —
  ~40% of underwriter time on data gathering, 3–8 week TAT, ~$350 APS orders, NIGO
  loops, inter-underwriter inconsistency — then state what the AI platform changes.
  Figures labeled industry-typical.
- **Demo flow**: the tour now shows **one complete journey first** — sign in as the
  junior analyst (authority-limited desk, SLA clocks, NIGO return), automatic
  escalation by authority to the senior desk, then the flagged case through every
  tab to the decision — before proceeding to manager / executive / admin personas.

## §E — SHIPPED · Configurable executive reporting

**⚙ Customize view** on the Executive Overview: any reporting block (headline tiles,
P&L, cost-to-underwrite, growth tiles, YoY, ops tiles, decision mix, appetite levers)
can be shown or hidden; the choice persists per browser. Different stakeholder groups
keep different views of the same live numbers. (Grouping extracted fields by report
category noted as a future enhancement — no UI change required now.)

## §F — SHIPPED · Integration coverage panel

Admin view now carries **"Integration coverage — where the platform sits in the
estate"**: internal systems (New Business Platform, Agent/Producer Portal,
Notification Services, CRM, Claims) and external systems (risk-assessment data
